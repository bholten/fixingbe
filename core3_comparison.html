Core3 vs. Simple Model: Creature Level

The Question

SWGEmu’s Core3 computes a pet/creature level (CL) from a creature’s realized combat stats with a fairly involved formula (HAM lookup tables, DPS/hit/regen level bands, an armor term, and a two-pass “defense level” blend). This project has independently reverse-engineered a much simpler two-branch linear model straight from the historical Furrycat data.

Now that the DNA Lab simulator can run Core3’s real level code path headless, we can put both predictors side by side against the one thing that is not a model — the actual, empirically measured retail levels — and ask: which is closer?

Method

For each cleaned creature (the same filtered set the rest of this project uses) we produce three numbers:

  • actual — the retail-measured CL (creatures.csv$level).
  • simple model — our custom_model(): the M8 unarmored branch / clean armored branch, keyed on the fortitude=500 split.
  • Core3 — the real Genetics::calculatePetLevel path, invoked through the dna-lab-level binary built with -DUSE_CORE3_LIBS=ON (i.e. linked against the actual Core3 libraries, not a re-implementation).

Two things worth stating plainly:

  1. Different inputs, same target. Core3 is fed each creature’s realized combat stats (HAM, damage, speed, to-hit, armor, resists) directly from creatures.csv; effectiveArmor is derived inside Core3 as sum(resists) * 2 (the verified crafting-time semantics). Our simple model is fed the genetic attributes. Both are judged only by how close their output lands to the actual level.

  2. In-sample caveat. Our model’s coefficients were fit on this very data; Core3’s were not. So the raw comparison flatters the simple model. The cross-validation section below refits the simple model’s structure on held-out folds to give it an honest out-of-sample test — Core3, having no fitted parameters here, is already out-of-sample everywhere.

Honest test: cross-validated simple model

The simple model’s coefficients were fit on this data, so its in-sample RMSE understates true error. Here we refit the simple model’s linear structure (same terms, same fortitude=500 split) on 10 random folds and score each held-out fold. Core3, having no fitted parameters, uses its fixed predictions.

Out-of-sample: simple model refit per fold vs. fixed Core3.
Model n RMSE MAE Bias R2 within +/-1 within +/-2
simple (10-fold CV) 370 1.912 1.424 -0.021 0.982 0.473 0.749
core3 (fixed) 370 5.373 3.927 1.986 0.857 0.332 0.505

Even out-of-sample, the simple model’s error is a fraction of Core3’s. The gap is not an artifact of over-fitting — the reverse-engineered formula genuinely tracks the retail levels better than the current Core3 implementation.

Takeaways

  • Against the actual retail data, the simple two-branch model is substantially more accurate than Core3 (RMSE ~1.8 vs ~5.4), and this survives cross-validation.
  • Core3 systematically overshoots unarmored creatures by ~2 levels; it is far better calibrated on armored creatures.
  • This is evidence — not a mandate — that the reverse-engineered formula is a candidate to simplify and improve the Core3 level calculation, especially for unarmored pets. Reproducing this comparison only requires rebuilding dna-lab-level and running R/core3_comparison.R.
